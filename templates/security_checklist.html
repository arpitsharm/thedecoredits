CPU USAGE

💻 CPU Abuse Prevention (KVM 1 - 1 Core)

Why KVM 1 CPU Gets Abused

  • Too many Gunicorn workers - each worker eats CPU+RAM
  • Infinite loops in Python code
  • Crypto miners (malware)
  • Bot traffic hitting your site non-stop
  • Chatbot API calls without rate limiting
  • Django debug toolbar left on in production

Safe Gunicorn Config for KVM 1

# For KVM 1 (1 vCPU, 1GB RAM) - MAX 3 workers gunicorn thedecoredits.wsgi:application \ --workers 3 \ --threads 2 \ --bind 127.0.0.1:8000 \ --timeout 120 \ --max-requests 1000 \ --max-requests-jitter 50 # Workers formula: (2 x CPU cores) + 1 # KVM 1 = 1 core = (2*1)+1 = 3 workers MAX

Monitor CPU Usage

# Check CPU usage top -bn1 | head -5 # Check which process uses most CPU ps aux --sort=-%cpu | head -10 # Check Gunicorn workers ps aux | grep gunicorn # Continuous monitoring htop

ABUSE PREVENTION

🔴 1. Compromised VPS / Hacked Server

  • SSH password leak
  • Weak admin password
  • Root access stolen
  • Hacked website access

Attackers may run:

  • Crypto mining
  • Spam sending
  • Bot networks
  • Malicious scripts
# Check for suspicious processes ps auxf | grep -v root | head -30 # Check for miners ps aux | grep -E "mine|xmrig|kdevtmpfsi|kinsing" # Check crontab for malware crontab -l cat /etc/crontab

🔴 2. Malware / Virus

  • Miner software (xmrig, kinsing)
  • Backdoors
  • Web shells
  • Suspicious Python/PHP scripts
# Scan for suspicious files find /tmp -type f -executable -ls find /var/tmp -type f -executable -ls find / -name "xmrig" -o -name "kinsing" 2>/dev/null # Check for suspicious network connections netstat -tlnp ss -tlnp

🔴 3. High CPU Abuse

  • Too many Gunicorn workers (KVM 1: max 3)
  • Infinite loops in code
  • Background tasks running forever
  • Bot traffic / DDoS
  • Mining malware
# Kill all gunicorn and restart clean pkill -f gunicorn sleep 2 gunicorn thedecoredits.wsgi:application --workers 3 --bind 127.0.0.1:8000 # Check for high CPU processes ps aux --sort=-%cpu | head -10

🔴 4. Spam Email Activity

  • Fake emails from your server
  • Bulk emails / mailer scripts
  • Phishing emails
# Check admin access logs grep "admin" /var/log/nginx/access.log | tail -20 # Check for brute force attempts grep "Failed password" /var/log/auth.log | tail -20

🔴 8. Open Ports / Services

  • Public database access (SQLite/PostgreSQL)
  • Redis exposed to public
  • Docker API exposed
  • SSH without protection
# Check open ports netstat -tlnp ss -tlnp # Check firewall status ufw status verbose iptables -L -n

🔴 9. Stolen API Keys

  • Payment keys (PayTM)
  • SMTP passwords
  • Database passwords
  • OpenRouter API key (currently hardcoded!)

🔴 10. Outdated Software

  • Old Django versions
  • Old Python packages
  • Old Ubuntu packages
  • Security vulnerabilities
FIREWALL

🛡 Firewall Setup for KVM 1

# Install UFW firewall sudo apt install ufw -y # Default policies sudo ufw default deny incoming sudo ufw default allow outgoing # Allow SSH (change port if you changed SSH port) sudo ufw allow 22/tcp # Allow HTTP and HTTPS sudo ufw allow 80/tcp sudo ufw allow 443/tcp # Enable firewall sudo ufw enable sudo ufw status verbose # Block specific IP if needed sudo ufw deny from 1.2.3.4

Setup CPU Alert Script

# Create alert script sudo nano /usr/local/bin/cpu_alert.sh # Content: #!/bin/bash THRESHOLD=80 CPU=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}') if (( $(echo "$CPU > $THRESHOLD" | bc -l) )); then echo "ALERT: CPU usage is ${CPU}% on $(hostname)" | \ mail -s "CPU Alert - KVM 1" your@email.com fi # Make executable sudo chmod +x /usr/local/bin/cpu_alert.sh # Add to crontab (check every 5 minutes) crontab -e # Add: */5 * * * * /usr/local/bin/cpu_alert.sh

FINAL RULES

🛡 KVM 1 Safety Rules

  • Keep Django DEBUG OFF always in production
  • Gunicorn workers = 3 MAX for KVM 1 (1 core)
  • Use strong passwords for SSH and admin
  • Enable UFW firewall - only allow 22, 80, 443
  • Use SSH keys instead of passwords
  • Update packages regularly
  • Monitor CPU - keep below 80% average
  • Check processes daily for miners/malware
  • Backup your VPS regularly
  • Never expose database ports publicly
  • Rate limit chatbot API to prevent abuse
  • Move API keys to environment variables
